## 0. 调研摘要：竞品与同类 UI 方案

调研了 6 个直接/间接竞品与设计系统，核心发现如下。

### 0.1 直接竞品（macOS 菜单栏 Agent 监控类，验证了需求真实性）

| 产品 | 形态 | 状态模型 | 可借鉴点 | 局限（我们的机会） |
|---|---|---|---|---|
| **Irrlicht** | 菜单栏图标列 | 4 态：working 紫 / waiting 橙 / ready 绿 / 空闲白 | "Files → State → Light" 确定性状态机哲学；前 5 个会话独立展示，7+ 时溢出省略；上下文压力分级（safe/caution/warning/critical） | 仅 macOS；菜单栏形态无浮动可见性；无声音/系统通知联动 |
| **Agent Signals** | 菜单栏红绿灯计数器 | 3 态计数：黄=待输入 / 绿=运行中 / 灰=完成 | "计数器聚合"是最小成本的多任务表达；点击条目直达 iTerm 标签页 | 只 3 态、无错误/超时/断连；无详情面板 |
| **AgentMicro** | 菜单栏状态灯 | 6 态：思考 / 未读结果 / 需输入 / 错误 / 空闲等 | 证明"六态"是社区收敛后的完备集；工作中任务置顶排序 + 项目名 + 当前轮次时长 | 仅 Codex 单一 agent；无泛化接入 |
| **AI Done Now** | 菜单栏通知器 | 完成事件驱动 | 原生系统通知 + 声音 + 点击聚焦对应窗口的交互闭环 | 闭源付费、仅 macOS、仅 Cursor/Claude Code |

**结论**：Windows 平台在此品类是空白（全部竞品为 macOS-only），且"悬浮球（自由位置浮动窗）"形态无竞品采用——菜单栏形态在 Windows 上无原生对应物，系统托盘又过于隐蔽。**悬浮球 + Windows 优先 = 差异化空位。**

### 0.2 高密度小窗体的行业范式

| 参考 | 借鉴点 |
|---|---|
| **RTSS / MSI Afterburner 游戏 OSD** | 极小体积常驻、颜色编码按指标分组、位置/透明度/缩放全可调、按程序记忆位置、热键开关、CPU 开销 <0.1% 的"感觉不到存在"哲学 |
| **VS Code 状态栏** | 远程指示器 + 加载 spinner + 错误/警告计数徽章 + 分支标签，证明 22px 高度内可以承载 5 类并行状态而不显拥挤；等宽字体用于数字/路径建立"数据感" |
| **Raycast** | 悬浮窗"呼出即用、失焦即走"的轻交互模型；键盘可达性（全部操作可无鼠标完成）作为一等公民 |
| **Linear 设计系统** | 暗色高对比（bg #08090A）、全产品仅 4 级字号（11/13/15/22）、密度即品牌签名、80-120ms 极简动效、"圆角不超过 8px、卡片无阴影"的克制条款 |
| **Vercel Geist** | 状态徽章语义映射铁律：green=healthy / red=error / amber=warning / blue=informational / gray=neutral；密集表面用 -subtle 降饱和变体；**"不要只靠颜色传达含义"（文字必须独立可读）**——直接决定我们的六态系统设计 |

## 1. 对标品牌与理由

**主对标：Linear（暗色密度）+ Vercel Geist（状态语义）+ Raycast（悬浮窗交互）**

| 对标 | 借什么 | 为什么 |
|---|---|---|
| **Linear** | 暗色基调、亮度递进分层、克制的单一强调色、高信息密度排版（11-15px 字号阶梯） | 目标用户（开发者）对该视觉语汇有"专业可信"的直觉认知；悬浮球详情面板本质是 Linear 式的高密度列表 |
| **Vercel Geist** | 状态色的语义映射规则、"色点不色块"的状态表达、subtle 变体降饱和 | 我们的产品核心就是状态传达，Geist 的 Badge/StatusDot 规范是业界最清晰的状态色纪律 |
| **Raycast** | 悬浮窗的轻量交互模型、键盘可达、失焦自动收起 | 悬浮球展开面板的行为范式直接参照：展开快（<200ms）、离开慢收起（300ms 延迟防误触） |
| **RTSS（反面对照）** | 可配置性边界 | 借鉴其位置/透明度记忆与低开销哲学，但拒绝其"全裸数据堆叠"的无引导体验——我们需要空状态引导和事件历史 |

**设计语言一句话**：像 Linear 一样安静克制，像 Geist 一样语义精确，像信标（Beacon）一样在状态变化时被立刻看见。

## 2. 设计语言

### 2.1 配色基调：暗色优先 + 跟随系统

**决策**：暗色优先（默认强制暗色，提供"跟随系统"选项，不提供浅色为默认）。

理由：目标用户是运行 CLI agent 的开发者，90%+ 工作在暗色终端/IDE 中；悬浮球是"背景常驻物"，暗色半透明在任意桌面壁纸上都比浅色更不突兀；六态状态色在深底上的对比度余量更大。浅色主题作为跟随系统的自动切换项支持，不单独作为品牌视觉打磨重点。

**色彩 Token 骨架（暗色主题，Phase 2 产出完整 design-tokens.json，本节为方向定义）**：

```css
:root[data-theme="dark"] {
  /* A1-identity 表面层（GitHub Dark 系亮度递进，开发者最高熟悉度） */
  --bg: #0D1117;            /* 面板底 */
  --surface: #161B22;       /* 卡片/悬浮球底 */
  --surface-warm: #21262D;  /* 行 hover / 三级表面 */
  --border: #30363D;
  --border-soft: rgba(255, 255, 255, 0.06);

  /* A1-identity 前景层 */
  --fg: #F0F6FC;
  --fg-2: #D0D6E0;
  --muted: #8B949E;
  --meta: #484F58;

  /* A2 强调色（品牌 accent，每屏 ≤2 处） */
  --accent: #2563EB;        /* 交互强调：跳转按钮、选中态、focus ring */
  --accent-on: #FFFFFF;

  /* A2 语义状态色（六态系统，见第 4 节） */
  --state-running: #3B82F6;   /* 进行中（蓝） */
  --state-waiting: #D29922;   /* 等待输入（琥珀） */
  --state-done: #3FB950;      /* 完成（绿） */
  --state-error: #F85149;     /* 错误（红） */
  --state-timeout: #DB6D28;   /* 超时（橙） */
  --state-offline: #8B949E;   /* 断连（灰） */

  /* 透明度 Token（悬浮球半透明专属，C-extension） */
  --orb-idle-alpha: 0.55;     /* 平时 */
  --orb-hover-alpha: 0.95;    /* 悬停/展开时 */
  --panel-alpha: 0.96;        /* 详情面板背景（近实底，保证文字对比度） */

  /* 精灵眼球体 Token（C-extension，Grok 式黑色球体 + 动画眼睛） */
  --orb-body: #0D1117;        /* 球体本色（深邃黑，与面板底色同值） */
  --orb-highlight: #21262D;   /* 球体高光（非渐变，低透明度椭圆模拟球面） */
  --eye-white: #F0F6FC;       /* 眼白 */
  --eye-pupil: #0D1117;       /* 瞳孔（与球体同色，形成"黑洞"效果） */
  --eye-highlight: #F0F6FC;   /* 瞳孔高光点（小圆点，增加灵气） */
}
```

色彩纪律（继承 Geist/Linear）：
- 状态色**只以色点、色环、色边形式出现**，绝不作大面积背景填充（错误行 = 红色状态点 + 红色文字标签，不是红色背景行）
- `--accent` 每屏 ≤2 处：面板中只用于"跳转主按钮"与"选中行左侧指示条"
- 中性色占 85%+，状态色合计 ≤10%，accent ≤5%

### 2.2 字体方向

```css
--font-body: "Inter", "Noto Sans SC", system-ui, sans-serif;  /* 界面文字 */
--font-mono: "JetBrains Mono", "Cascadia Code", Consolas, monospace;  /* 数据文字 */
```

- **双字体纪律**：界面用 Inter/Noto Sans SC；所有"机器数据"（工具调用名、时长、token 数、会话 ID）一律 JetBrains Mono——等宽字体是开发者工具信任感的最大来源（VS Code 状态栏、Linear、Geist 全部如此）
- **Linear 式紧字号阶梯**（驾驶舱密度）：11px（元数据/标签）/ 13px（正文/任务名）/ 14px（面板标题）/ 20px（设置窗口页标题），不设更大字号——本产品无营销场景
- 字重三级：400 正文 / 510 次标题与任务名 / 590 面板标题
- ALL CAPS 标签（如 "RUNNING"）letter-spacing ≥ 0.06em
- **悬浮球本体零文字**：球体纯图形语言，最小尺寸下文字必然不可读

### 2.3 圆角与密度

- 圆角阶梯：6px（行内小元素）/ 8px（按钮、输入框、**悬浮球详情面板**——遵守 Linear "圆角 ≤8px" 条款）/ 12px（设置窗口、模态）/ full（悬浮球、状态点）
- 行高纪律：任务列表行高 40px（含 8px 上下内距），密度介于 Linear（32px）与 VS Code（24px）之间
- 分组用 `--border-soft` 1px 分隔线，不用卡片嵌套卡片（VISUAL_DENSITY=8 时禁用通用卡片容器）

### 2.4 动效原则

功能性动效，零装饰动画（MOTION_INTENSITY=4）：

| 场景 | 时长/节奏 |
|---|---|
| 悬浮球 hover 透明度提升 | 150ms ease-out（知识库收敛值） |
| 详情面板展开/收起 | 220ms，自悬浮球位置向右展开（空间连续性） |
| 状态切换（球体变色） | 200ms 颜色过渡 + 状态动画重置 |
| 完成事件弹跳反馈 | 单次 250ms scale 1.0→1.08→1.0，仅此一处"愉悦时刻" |
| 状态持续动画（六态） | 见第 4 节，全部循环动画遵守线性缓动、无弹跳 |

强制支持 `prefers-reduced-motion`：所有循环状态动画降级为静态图标 + 状态色（详见第 7 节）。

### 2.5 图标系统（文字定义，具体库由架构师在 Spec 锁定）

全项目统一一套描边 SVG 图标库（建议候选：Lucide —— MIT 开源、2px 描边、与 Tauri/Rust 生态打包友好；最终由架构师锁定），尺寸 16px（行内）/ 20px（按钮内）/ 24px（设置/面板图标）。**悬浮球中心不使用图标库图标——中心为自定义 SVG 眼睛动画系统**，由前端用 CSS/SVG 手绘实现。Lucide 仅用于详情面板、设置窗口、系统托盘等功能性 UI 图标。六态的眼睛表情语义定义见第 4 节，均为自定义 SVG/CSS 实现。

## 3. 悬浮球形态方案（2 方案对比 + 推荐）

### 方案 A：精灵眼信标球（推荐——Grok 式黑色球体 + 动画眼睛）

**形态描述**：48px 正圆，三层结构——
- **外层：3px 环形指示环**，按会话分段（每段弧 = 一个会话，弧长按任务运行时长占比），段的颜色与动画 = 该会话的状态。**此层不变，负责多会话并行展示。**
- **中层：实心球体**，纯黑 `#0D1117`（Grok 风格深邃黑），半透明常驻。球体表面有微弱高光（`#21262D` 低透明度椭圆，模拟 3D 球面感，非渐变）。
- **中心：两只白色动画眼睛**（取代原方案的 24px 静态图标），表达"最高优先级状态"的精灵表情。眼睛由白色眼白（`#F0F6FC`）+ 深色瞳孔（`#0D1117`）组成，通过瞳孔位移、眼形变化、开合动作实现六态表情。

**交互**：
- 默认半透明（`--orb-idle-alpha`），hover 提升至 0.95 并轻微放大至 52px（150ms）
- 单击左键展开详情面板；拖动移动位置（拖动阈值 4px 区分点击/拖动）；右键快捷菜单（勿扰/退出/设置）
- 双击 = 跳转最高优先级任务的窗口（快动作，供熟手）

**为什么推荐**：
1. **精灵眼 = 产品人格**——两只动画眼睛让悬浮球从"指示灯"升级为"小精灵"，用户对它产生情感连接（Grok 黑球已验证这一吸引力），"你的 Pupil 在盯着 Agent"比"状态灯亮了"更有记忆点
2. **环形 = 天然的多任务聚合画布**——2~5 个并行会话各有独立弧段，一眼分辨"两个在跑、一个在等我"，这是纯色球做不到的
3. 状态可辨识不依赖尺寸——48px 的环上，"旋转的蓝色弧"vs"呼吸的琥珀弧"在视觉边缘就能区分，符合"余光可读"目标
4. 有行业心智先例（Apple Watch 活动环、Linear 循环进度），无需学习成本
5. 信息分层清晰：环=全部会话，眼睛=当前最需要关注的那个状态的精灵表情

### 方案 B：纯色极简球 + 角标计数

**形态描述**：32px 纯色小圆球，整体颜色 = 最高优先级状态色，右上角 14px 圆形角标显示活跃会话数（数字 ≤9，超过显示 "9+"）。

**优点**：体积最小（32px），遮挡最少，实现最简单，远看像一枚"状态灯"。
**致命缺点**：
1. **一次只能表达一个状态**——3 个会话 2 个运行 1 个报错时，球体只能显示错误色，用户无法知道还有 2 个在正常跑
2. 角标数字在 14px 下依赖视力，且数字不含状态信息
3. 球体整体着色 = 状态色大面积使用，违反"状态色只作色点/色环"纪律，在壁纸上过显突兀

**裁决**：方案 A 为主方案。方案 B 降级为其**子模式**——设置中提供"极简模式"开关（用户自觉遮挡敏感时切换），体现 RTSS 式可配置哲学。默认 A。

### 3.3 多任务聚合规则（两方案共用）

- **状态优先级**（高→低）：error > timeout > offline > waiting > running > done；眼睛表情与通知取最高优先级
- 会话数 ≤5：环分 ≤5 段，每段独立动画；眼睛显示最高优先级态的表情
- 会话数 ≥6：环合并为单一颜色（最高优先级态），眼睛表情不变（仍表达最高优先级态），面板内显示总数与逐会话明细
- 完成的会话：对应弧段变绿后 30 秒淡出移除；若全部完成，眼睛回到空闲/休眠态
- 环无会话时：中性灰细环 + 眼睛闭合并拢（休眠态，低存在感）

## 4. 六态状态系统定义（色彩 + 动画 + 图标）

设计铁律（源自 Vercel Geist "Don't rely on color alone"）：**每个状态 = 色相（外环）+ 眼睛表情（球心）+ 动画模式 三重编码**，任一通道丢失（色弱、动画被禁用、球体过小）仍可辨识。色相选择已做红绿色盲规避：六色中仅 done/error 存在红绿轴冲突，由眼睛表情与动画兜底。

| 状态 | Token | 环色值（暗底） | 环动画 | 眼睛表情 | 眼睛动画 | 语义 |
|---|---|---|---|---|---|---|
| **加载中** initializing | `--state-running` | 蓝 #3B82F6 | 环段虚线短促闪动 | 双眼睁开，瞳孔左右快速游移 | 瞳孔在眼白内水平快速移动（0.5s/次方向切换），如四处搜寻 | 适配器初始化/会话发现中 |
| **进行中** thinking/running | `--state-running` | 蓝 #3B82F6 | 弧段沿环匀速旋转（1.2s/圈，线性） | 双眼睁开，瞳孔微偏一侧 | 瞳孔缓慢游移 + 每 4-6s 眨眼一次（120ms 闭→开），专注但有活力 | 模型在思考/流式输出/工具执行中 |
| **等待输入** waiting | `--state-waiting` | 琥珀 #D29922 | 呼吸脉冲（2s 周期，不透明度 0.45↔1.0） | 双眼睁大，瞳孔放大居中，直视用户 | 瞳孔保持居中不放大的"凝视你"姿态 + 每 2s 眨眼一次（比 running 频繁，传达"催促"） | Agent 暂停等待用户确认/授权 |
| **完成** done | `--state-done` | 绿 #3FB950 | 无循环动画；进入瞬间单次 250ms 弹跳后静止 | 开心眯眼（两条上弧线 ^ ^） | 250ms 单次：眼睛从睁开 → 上弧眯眼 + 球体轻微弹跳 scale 1.0→1.08→1.0，之后保持眯眼静止 | 回答完成/任务结束，尚未查看 |
| **错误** error | `--state-error` | 红 #F85149 | 快闪 3 次（200ms/次）后转常亮 1Hz 慢闪 | X X 眼（两个叉号替代眼球） | 眼睛瞬间变 X → 外环快闪 3 次 → 之后 X 眼保持 + 外环 1Hz 慢闪 | 进程报错/工具执行失败 |
| **超时** timeout | `--state-timeout` | 橙 #DB6D28 | 1s 周期慢闪（占空比 70%） | 双眼半开，瞳孔偏向一侧（不耐烦地斜视） | 瞳孔每隔 1s 向同侧快速偏移再回位（与环慢闪同步），模拟"看表"的不耐烦动作 | 任务运行超时阈值 |
| **断连** offline | `--state-offline` | 灰 #8B949E | 完全静止（无动画=最弱存在感） | 闭眼（两条短水平线），球体变暗（opacity 0.65） | 静止 + 球体上方偶尔飘出小 "z" 文字（2s 间隔渐隐） | 会话进程退出/心跳丢失/连接中断 |
| **空闲** idle | `--state-offline` | 灰 #8B949E | 极细中性灰环，无动画 | 闭眼（两条短水平弧线，略带微笑弧度） | 每 5-8s 眼睛缓慢开合一次（模拟浅睡呼吸），极低存在感 | 无任何会话被监控 |

**色弱友好专项**（第 7 节详述）：
- waiting 琥珀 vs timeout 橙：色相接近（这是有意的——同属"需要注意但非致命"族），靠动画频率（呼吸 2s vs 慢闪 1s）+ 眼睛表情（凝视 vs 斜视不耐烦）区分
- done 绿 vs error 红：红绿色盲最难对，靠动画（静止 vs 闪烁）+ 眼睛表情（开心眯眼 vs X 眼）+ 完成态 30 秒后淡出的行为差异兜底
- running 蓝：六色中唯一冷色相，蓝色盲（极罕见）由旋转动画 + 瞳孔游移动作兜底

**声音与系统通知映射**（同一状态机的第二/第三输出通道）：

| 状态 | 提示音（可关） | 系统通知 |
|---|---|---|
| done | 单音"叮"（默认开） | 有："payment-api 重构 已完成 · 运行 12:47" |
| waiting | 双音提示（默认开） | 有："Codex 会话等待你的确认" |
| error | 低沉短音（默认开） | 有："任务失败 · Bash npm test 退出码 1" |
| timeout | 低沉双音（默认开） | 有："订单报表脚本 已超时 · 运行 30:00" |
| offline | 无 | 有："连接中断 · Hermes 会话已退出" |
| running | 无（不打扰） | 无 |

通知正文一律真实内容（会话名/工具/时长/退出码），点击通知跳转对应工具窗口——这是 AI Done Now 已验证的核心闭环。

## 5. 详情面板信息架构

### 5.1 结构（自悬浮球向右展开，宽 360px，最大高 480px）

```
┌─────────────────────────────────────┐
│ [1] 顶栏（高 44px）                   │
│  3 运行 · 1 待输入 · 1 完成   [月形] [齿轮] │
├─────────────────────────────────────┤
│ [2] 会话列表（按优先级排序，行高 40px）    │
│  ● payment-api 重构        Claude Code │
│    Read src/api/payments.ts    12:47 [↗] │
│  ─────────────────────────────────── │
│  ● 订单报表脚本            Codex       │
│    等待确认：是否执行 rm 临时文件   03:22 [↗] │
│  ─────────────────────────────────── │
│  ● 灰度发布清单生成          Hermes     │
│    已完成 · 点击查看结果         08:15 [↗] │
├─────────────────────────────────────┤
│ [3] 底部页签（高 36px）                │
│  会话  ｜  事件历史                    │
└─────────────────────────────────────┘
```

### 5.2 分区定义

**[1] 顶栏**：左侧文本汇总（"3 运行 · 1 待输入 · 1 完成"，数字用等宽字体，各状态文字带对应色点）；右侧两个 20px 图标按钮：勿扰模式（月形图标，激活时着 `--state-waiting` 色）与设置（齿轮图标）。勿扰激活时顶栏底色加 `--surface-warm` 微弱提示。

**[2] 会话列表行**（每行四元素，点击整行跳转对应窗口）：
- **状态点**（8px 圆点，状态色 + 对应动画）——余光扫描锚点
- **会话身份**：任务名（13px/510 字重）+ 来源工具标签（11px，`--muted`，如 "Claude Code" / "Codex" / "Hermes" / 自研 Harness 名）
- **当前活动**（11px 等宽，`--muted`）：running 显示当前工具调用（`Read src/api/payments.ts`）；waiting 显示待确认摘要（"等待确认：是否执行 rm 临时文件"）；done/error/timeout/offline 显示结果或原因（"已完成 · 点击查看结果" / "Bash npm test 退出码 1"）
- **运行时长**（11px 等宽，右对齐）：`12:47` 格式，mm:ss，超 1 小时转 `1:12:47`
- 行 hover：背景 `--surface-warm`，右侧浮现 [↗] 跳转图标按钮（16px，`--accent`——全屏唯一 accent 使用点之一）
- 错误/超时行：状态点旁追加 11px 文字标签（"失败" / "超时"），不只靠颜色

**[3] 底部页签**：「会话」（默认）/「事件历史」。事件历史 = 时间倒序列表（"14:32 完成 payment-api 重构 · 12:47" / "14:28 错误 Bash npm test · 订单报表脚本"），每行 = 时间（等宽）+ 事件类型（色点+文字）+ 会话名，保留最近 200 条，底部"清空历史"文字按钮。失败重试提醒：error 事件行尾追加"重试提醒"开关按钮（铃形图标），开启后该任务重试时强提醒。

**空状态**（未检测到任何会话）：
> 图标（雷达/搜索描边图形）+ 文案："未检测到运行中的 Agent 会话" + 次级文案："支持监控 Claude Code、Codex、Hermes 等工具的后台会话" + 主按钮"查看接入指引"（accent 按钮）。

**加载态**：面板骨架（3 行 shimmer 占位）+ 顶栏 spinner，仅在监控源初始化时短暂出现。

### 5.3 面板行为

- 展开动画 220ms 自球体位置向右弹出（transform-origin 左侧）
- 失焦自动收起（300ms 延迟防误触）；Esc 键收起；面板打开时悬浮球保持 0.95 不透明度
- 会话 >6 条时列表内滚动，顶栏吸顶
- 面板背景 `--bg` @ `--panel-alpha` 0.96 + 1px `--border` + 8px 圆角 + 轻阴影（`0 8px 24px rgba(0,0,0,0.4)`）——半透明留 4% 透出壁纸，保持"悬浮"心智但保证 13px 文字对比度

## 7. 无障碍考量

### 7.1 色弱/色盲友好（六态三重编码，见第 4 节）

- **不只靠颜色**：每态 = 色相 + 眼睛表情 + 动画模式三通道。色觉缺失用户靠"X 眼"vs"开心眯眼"完成区分
- 红绿轴（done/error）与琥珀橙轴（waiting/timeout）均设动画频率差（静止/快闪 与 呼吸 2s/慢闪 1s）
- 状态色避开紫粉区（同时满足 P0-2 禁令）；running 选蓝——蓝琥珀对比是色觉无障碍的经典安全组合

### 7.2 对比度（WCAG 2.1）

- 正文 13px 文字（`--fg` #F0F6FC on `--bg` #0D1117）：约 16:1
- 次级文字（`--muted` #8B949E on #0D1117）：约 4.9:1，达标 4.5:1
- 状态色（图形用途，需 3:1）：六色对 #0D1117 全部 ≥4.5:1，余量充足；悬浮球在浅色壁纸上时环与图标描边外加 1px `--border` 深色描边保证边界
- 通知正文遵守系统级对比度（走 Windows 原生 toast 渲染）

### 7.3 运动敏感

- `prefers-reduced-motion: reduce` 时：全部循环动画（环旋转/呼吸/闪烁/瞳孔游移）降级为静止状态色 + 眼睛表情（表情不变，只是不循环动画）；弹跳反馈降级为透明度单次渐变；面板展开降级为 0ms 直出
- 闪烁频率上限约束：error 快闪 200ms/次 = 2.5Hz，低于光敏性癫痫安全阈值 3Hz；可再提供"关闭所有闪烁"设置项

### 7.4 键盘与焦点

- 面板打开后焦点移入列表首行；↑↓ 在行间移动，Enter 跳转，Esc 收起，Tab 在顶栏/列表/页签间循环
- 全部图标按钮有 focus-visible 环（`0 0 0 3px rgba(37,99,235,0.4)`）+ aria-label（勿扰按钮标注"切换勿扰模式"而非裸图标）
- 悬浮球本体提供全局热键（默认 Alt+Shift+A，可改）呼出面板，纯键盘用户全程可达（Raycast 式承诺）

### 7.5 触摸/点击目标

- 悬浮球 48px（超过 44px 最小目标）；面板内行高 40px 但整行可点（>44px 等效）；顶栏图标按钮 20px 图标 + 8px 内边距 = 36px 热区，补 padding 扩至 44px
