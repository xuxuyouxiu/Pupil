### 本机沙箱运行 Electron 的两大坑（重要）
1. **ELECTRON_RUN_AS_NODE 变量注入**：WorkBuddy 沙箱环境注入 `ELECTRON_RUN_AS_NODE=1`，Electron 检查"变量是否存在"（非值），导致 electron.exe 以纯 Node 模式跑（process.type=undefined、require('electron') 返回 npm 桩路径字符串、electron.app undefined 崩溃）。修复：`env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS npm run dev`（`VAR=` 设空无效，必须彻底 unset）
2. **Chromium 进程沙箱在受限环境初始化失败**：GPU 进程连环崩溃 exit_code=1 → `FATAL:gpu_data_manager_impl_private.cc(423)] GPU process isn't usable`。修复：main/index.ts 里 `app.commandLine.appendSwitch('no-sandbox')` + `app.disableHardwareAcceleration()`（代码内生效，无需命令行参数）
- 已写入 src/main/index.ts 顶部（no-sandbox + disableHardwareAcceleration），提交后其他环境同样受益
- 排查过程：镜像下载的 electron zip 只有 73 条目、无 electron.asar —— 但经 GitHub HEAD 验证（Content-Length 115028145 与镜像一致），**新版 Electron 本来就不带 electron.asar**（JS 已编译进二进制），zip 是完整的，虚惊一场
- 教训：先核对官方资产大小再怀疑镜像损坏；Git Bash 删 Windows 绝对路径文件会被 safe-delete shim 路径拼接搞坏，改用 PowerShell 处理

## 悬浮球可见度 + 拖动修复（用户反馈"看不清 + 两根橙色线"）
- 现象：球在浅色壁纸上 0.55 透明导致"看不清"；hover 变实心无效；球旁边有"两根橙色线"
- 用 GDI 截屏（Python ctypes，无 PIL）+ 像素分析定位：橙色 = **超时状态环 #db6d28**（之前测试会话 17 分钟无事件被 InferenceEngine 标记超时），非 bug；"看不清" = idle 0.55 透明 + 深色球体在浅色壁纸下被冲淡
- 根因 1：`-webkit-app-region: drag` 在 Windows 吞掉全部鼠标事件 → hover/click/右键/双击全失效。改 IPC 自定义拖动（pointer capture + 主进程 getCursorScreenPoint，DPI 安全）
- 根因 2：可见度分层缺失。新增 `--orb-active-alpha: 0.92`，活跃态更醒目，hover 强制 opacity 1（`:where()` 保证优先级）
- 新增 IPC 通道：ballDragStart/Move/End；WindowManager 加 startDrag/moveDrag/endDrag；Ball.tsx 用 onPointerDown/Move/Up + screenX/Y 判断点击 vs 拖动
- 新发现沙箱坑：`env -u` 会静默吞掉子进程 stdout（连 echo 都没输出），改用 `unset`。TaskStop 杀 npm 父进程会留 electron 孤儿 → 需 Stop-Process 补刀

  - `assistant` content 内 tool_use 块 → tool_call_started；`stop_reason:end_turn` → turn_completed
